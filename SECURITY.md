# Security Policy

## Reporting

Use GitHub private vulnerability reporting if it is enabled for this repository. If it is not enabled, open a minimal public issue that says a security report is available, but do not include exploit details, private data, or secrets.

## Scope

Security-sensitive reports include unsafe reference-runtime behavior, schema validation bypasses, dependency compromise, token exposure in workflows, and publication of private biomedical or identity data.

## Handling

Maintainers should confirm receipt, reproduce the issue in a private branch when needed, rotate any exposed credentials, and publish a fix with a short advisory or release note.
